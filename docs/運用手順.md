# 運用手順

CFTC COT ダッシュボードの日々の確認、設定変更、トラブル時の対処をまとめる。

- 公開URL：https://irregularprime-source.github.io/market-data-public/cot/
- ワークフロー：`.github/workflows/cot-weekly.yml`（名前は `COT weekly`）
- 実行履歴：https://github.com/irregularprime-source/market-data-public/actions

## 1. 実行スケジュール

| 項目 | 内容 |
|---|---|
| 定期実行 | 毎日 6:47 と 7:47 JST（cron は UTC で `47 21 * * *` / `47 22 * * *`） |
| CFTCの公表 | 通常は金曜 15:30 米東部時間（JST では夏時間 土曜 4:30／冬時間 土曜 5:30）。データは同じ週の火曜時点 |
| 祝日週 | 米国の祝日で公表が月曜などにずれる。毎日実行しているので、公表翌朝に自動で反映される |

- 公表スケジュール：[CFTC COT Release Schedule](https://www.cftc.gov/MarketReports/CommitmentsofTraders/ReleaseSchedule/index.htm)
- 1日2回のうち2回目は、通常「データ変更なし」で終わる（実行遅延・失敗に備えた再確認）。
- GitHub 側が混雑していると、開始が数分〜数十分遅れることがある。毎時0分は混みやすいため47分にしている。

## 2. 処理の流れ

1. `cot/config/markets.csv` の銘柄を対象に、CFTC Public Reporting API から7データセットを取得する（直近約3年＋12週分を毎回取り直す。過去週の訂正を反映するため）
2. `data/cot/*.csv` の履歴に上書き追記する
3. ネット・前週比・建玉比・COT指数を計算し、`site/cot/` にダッシュボード・Excel・全履歴CSVを出力する
4. `data/cot/` に差分があれば `github-actions[bot]` がコミットして push する（差分が無ければ「データ変更なし」）
5. `site/` を GitHub Pages に公開する

## 3. 日々の確認

ふだんは何もしなくてよい。動いているかを見たいときは次のどれかを確認する。

- ダッシュボード上部の「作成」日時が、当日の朝になっている
- ダッシュボードの「基準日」が、直近の火曜になっている（土曜朝以降。祝日週は公表日の翌朝以降）
- 実行履歴：

  ```bash
  gh run list --workflow "COT weekly" --repo irregularprime-source/market-data-public --limit 4
  ```

- 失敗した定期実行は、GitHub からメールで通知される（通知先はワークフローの cron を最後に変更したユーザー）。

### ログの `警告:` について

実行が成功（緑）でも、ログに次の警告が出ることがある。ワークフローは止まらないので、気になるときはログを確認する。

| 警告 | 意味 | 対処 |
|---|---|---|
| `○○（コード）が最新週 YYYY-MM-DD にありません` | 銘柄コードの変更・上場廃止・その週だけの欠測の可能性 | 翌週も続くなら CFTC 側で銘柄コードを確認し、`markets.csv` を直す |
| `○○/○○: データがありません` | データセットごと取れていない | この場合はワークフローが失敗扱いになる。下の「トラブル時の対処」へ |

## 4. 銘柄の追加・削除

`cot/config/markets.csv` を編集して commit・push すれば、次回の実行から反映される。

| 列 | 内容 |
|---|---|
| `code` | CFTC の銘柄コード（`cftc_contract_market_code`、6桁。先頭の0も残す） |
| `name_ja` | 表示名 |
| `asset_class` | 資産区分（金利、通貨、株価指数、エネルギー、金属、農産物、暗号資産）。ダッシュボードの絞り込みに使う |
| `tff` | 1 なら TFF（金融先物）の対象 |
| `disagg` | 1 なら Disaggregated（商品）の対象 |
| `cit` | 1 なら Supplemental CIT の対象（CFTC が CIT を公表している農産物のみ） |

- Legacy は、この表の全銘柄が対象（フラグ列は無い）。
- 行の並び順が、ダッシュボードとExcelの表示順になる。
- 銘柄コードは [CFTC Public Reporting](https://publicreporting.cftc.gov/stories/s/r4w3-av2u) の各データセットで `cftc_contract_market_code` を検索して確認する。
- 追加後すぐ確認したいときは、手動実行する（次の節）。

## 5. 手動実行

```bash
gh workflow run "COT weekly" --repo irregularprime-source/market-data-public
```

GitHub の画面からは Actions → COT weekly → Run workflow でも実行できる。

ローカルで確認する場合（`site/` に出力されるだけで、公開はされない。Python 3.11 以上が必要、Actions と同じ 3.12 を推奨）：

```bash
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q
python -m cot.run              # 取得から出力まで
python -m cot.run --no-fetch   # 保存済みデータから出力だけ作り直す
```

## 6. トラブル時の対処

失敗した実行は、そのまま放置しても次の定期実行で取り直される。前回の公開ページはそのまま残る。

| 症状 | 想定原因 | 対処 |
|---|---|---|
| Fetch and build で「取得に失敗しました」 | CFTC API の一時障害（3回まで自動で再試行している） | 次回の定期実行を待つか、時間をおいて手動実行する |
| Test が失敗 | 集計ロジックの変更ミス | 直前のコミットを確認する |
| Commit data で push が 403 | Workflow permissions が足りない | ワークフロー側で `contents: write` を指定している。それでも失敗するときは Settings → Actions → General → Workflow permissions を「Read and write permissions」にする |
| Commit data で push が rejected | 実行中に別のコミットが push された | 次回の実行で解消する。続く場合はログを確認する |
| deploy が「Pages not enabled」等で失敗 | Pages の公開元設定が外れた | 下の「初期設定」を参照して再設定する |
| deploy が environment 保護ルールで拒否 | `github-pages` 環境のブランチ制限 | Settings → Environments → github-pages で `main` を許可する |
| 定期実行がまったく動かない | 60日間リポジトリに動きが無く、GitHub が自動停止した | Actions → COT weekly で「Enable workflow」を押す |

## 7. 注意事項

- **60日停止ルール**：公開リポジトリは、60日間コミット等の動きが無いと定期実行が自動停止する。毎週のデータ更新コミットで通常は回避される。CFTC の公表が長期間止まった場合（米政府機関の閉鎖など）は停止しうる。
- **ランナーの切り替え**：`ubuntu-latest` は 2026-10-19 から Ubuntu 26 へ順次切り替わる。切り替え後に失敗し始めたら、ログを確認する（一時的に戻すなら `runs-on: ubuntu-24.04` に固定する）。
- **アクションのバージョン**：2026-10-07 に Dependabot の PR で Node.js 24 対応版（checkout v7、setup-python v7、upload-pages-artifact v5、deploy-pages v5）へ更新済み。以後の更新も Dependabot の PR で行う（下記）。
- **依存パッケージ・アクションの更新**：改ざん対策のため、`requirements*.txt` は版を固定し、ワークフローのアクションはコミットSHAで固定している。更新は Dependabot が毎週チェックし、更新があれば PR を作る（脆弱性の修正版は随時）。PR ではワークフローが動かないので、マージ後に手動実行して成功を確認する。
- **CIT は先物+オプション版のみ**：CFTC が Supplemental CIT を先物のみ版で公表していないため。
- **Search Console の確認ファイル**：`cot/googlec5a426f06dcfde4b.html` は Google Search Console（プロパティ `https://irregularprime-source.github.io/market-data-public/cot/`）の所有権確認用。ワークフローが毎回 `site/cot/` にコピーして公開している。削除すると確認が外れるので消さない。

## 8. 初期設定（リポジトリを作り直す場合）

1. このフォルダの内容を `main` に push する（`site/` は `.gitignore` 済みで、Actions が毎回作る）
2. Pages の公開元を「GitHub Actions」にする

   ```bash
   gh api -X POST repos/irregularprime-source/market-data-public/pages -f build_type=workflow
   ```

   画面からは Settings → Pages → Build and deployment → Source を「GitHub Actions」にする。
3. `COT weekly` を手動実行し、build・deploy の成功と公開URLの表示を確認する

## 9. 出典・免責

- データ出典：U.S. Commodity Futures Trading Commission (CFTC), Commitments of Traders。CFTC サイト上の政府情報はパブリックドメイン（[CFTC Web Policy](https://www.cftc.gov/webpolicy/index.htm)）。CFTC の紋章は使用しない。
- 本リポジトリの集計・表示は情報提供のみを目的としたもので、投資助言や売買の推奨ではない。
